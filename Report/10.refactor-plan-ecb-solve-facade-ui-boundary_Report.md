## 1. Executive Summary

본 세션에서는 `solve_facade.py`·`ui_boundary.py` 및 Entity solver 경로에 대해 **테스트 매핑**, **RED/REFACTOR 전제**, **ECB 역할·코드 스멜**, **리팩토링 계획서**를 Ask mode로 분석했다. production 코드 변경은 없다. 핵심 결론은 다음과 같다.

1. **Control 테스트 부재**(`tests/control/`) — REFACTOR §4.3 Rule 1(전체 pytest GREEN) 회귀망 약함.
2. **`solve_facade`가 `UIBoundary`를 소유** — `control→boundary` 의존으로 ECB §3.3 허용 방향과 불일치.
3. **`ui_boundary.submit`** — 입력·출력 검증, Domain 호출, 예외→E006/E007 매핑, DTO 조립이 한 함수에 집중.
4. **Entity `solution()`·`try_case_a/b`** — 레이어 위치는 적합; Port·메시지 SSOT·함수 다중 역할은 P1에서 분리.
5. **`main_window.py`·`two_cell_solver.py`** — 저장소 미존재; Screen·2-cell 역할은 `ux_presentation`·`completion_strategy`가 대체.

**REFACTOR 1순위(P0):** `tests/control` 추가 후 Control↔Boundary 의존 정리 + `submit` 예외 매핑 좁히기 — **E001~E007·`int[6]`·RG-03** 불변.
